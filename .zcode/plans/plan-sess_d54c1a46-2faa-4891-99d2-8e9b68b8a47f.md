# 上位机 + 下位机通信协议实现计划

## 已确认的前提（来自你的回答）
- 上位机：**Tkinter + pyserial**，uv 管理，`scripts/` 作为 uv 工程根
- 链路：**USB CDC 一根线**，协议二进制帧与现有 printf 日志共用同一串口，上位机自动分流
- 附加功能：**主机失联看门狗** + **CSV 记录 + 实时曲线**（不做掉电保存）
- 固件：**直接落盘**（新建模块 + 对 main.c / pcb_test / ui.c 做最小接入）

## 一、协议（v1，二进制帧）

链路上：`COBS(帧内容) + 0x00`。解码后帧结构（小端）：

| 偏移 | 长度 | 字段 |
|---|---|---|
| 0 | 1 | `cmd`（bit7=0 主机→设备；bit7=1 设备→主机） |
| 1 | 1 | `seq`（响应原样回填；设备主动上报用 0） |
| 2 | 1 | `len`（payload 0–48） |
| 3 | len | payload |
| 3+len | 2 | CRC-16/CCITT-FALSE（覆盖 cmd..payload） |

**为什么选 COBS + CRC16 + 二进制**：与 `docs/通信协议.xlsx` 里 IMU 模块的帧风格一致；`common_def.h` 里已有 `EXIT_CRC_MISMATCH`、`docs` 的协议惯例是包头+长度+功能字+校验；COBS 以 0x00 分帧，而 printf 文本里不会出现 0x00，所以日志文本夹在帧里只会导致**丢一帧**（CRC 不过就丢）而不会误解帧，重同步是自动的。最大帧 55 字节 < CDC TX FIFO 64 字节，保证一帧一次 `tud_cdc_write` 写完，不会被别的任务的 printf 插进中间。

**命令（主机→设备）**：`PING` / `GET_INFO` / `SET_VOUT{unit,val}` / `SET_ILIM{unit,val}` / `SET_OUTPUT{on}` / `SAFE_STATE` / `RUN_TEST` / `STOP_TEST` / `SET_TELEM{period_ms}` / `SET_REMOTE{enable,timeout_ms}` / `GET_STATUS` / `KEEPALIVE`

**响应与上报（设备→主机）**：`PONG` / `INFO`（协议版本、固件版本、板级常量：满量程 23400 mV、5040 mA、50 kHz、最小 3900 mV、测试项数、能力位，所以**上位机不重复写死任何板级常量**）/ `TELEM`（16 字节：flags、run_state、cur_index、pg_state、pwm‰、ipwm‰、pg_mv、vout_mv、tick_ms）/ `ACK`（被应答命令 + `exit_code_t` 码 + 附加数值）/ `EVENT`（安全态、测试开始/结束、看门狗超时、远程模式变化）/ `ITEM`（测试项 idx/name/result/elapsed/detail）/ `STATUS`（完整快照含 7 项结果码，重连后一次拿全）

**单位**：`SET_VOUT/SET_ILIM` 带 `unit` 字节，`0`=原始占空比‰（用于精确扫描），`1`=mV/mA（按人的思维设定）。mV→‰ 的换算在**固件侧**用 `board_config.h` 常量完成，越界返回 `EXIT_INVALID_PARAM`。遥测只发‰，mV/mA 显示值由上位机用 INFO 下发的常量算（信息单一来源）。

**可靠性与安全**：
- 命令带 `seq`，主机等 ACK 200 ms 超时重试 3 次
- 远程模式 + 看门狗：`SET_REMOTE{1,3000}` 后 3 s 内收不到任何有效帧 → 设备回安全态（CE# 关断 + 双 PWM 0%）+ `EV_WATCHDOG` 事件 + 自动退出远程模式；主机每 1 s 发 `KEEPALIVE`
- 远程模式下按键只保留长按急停（急停永远本地有效，并退出远程模式），屏幕显示 `RMT` 标识
- 上位机断开时默认先回安全态再退出远程（GUI 上可关掉这个默认）

## 二、下位机（固件）

新增：
- `src/lib/proto/psu_proto.h` / `.c` — 纯逻辑无 RTOS 依赖：CRC16、COBS 编解码、帧封装/解析、小端读写助手、命令与事件枚举、`PSU_PROTO_MAX_PAYLOAD 48`（返回 `exit_code_t`，CRC 失败返回 `EXIT_CRC_MISMATCH`）
- `src/app/psu_link/psu_link.h` / `.c` — USB CDC 收（`tud_cdc_read` 5 ms 轮询 + 增量 COBS 累积器，只用 TinyUSB 原始接口，不碰 stdio 的 RX 路径）、命令解释、看门狗、遥测定时、`psu_link_send_frame()`（等 `tud_cdc_write_available` 够了一帧一次写完，互斥锁保护）、`psu_link_log()`、`psu_link_task()`

改动（最小接入）：
- `pcb_test.h/.c`：把三个 volatile 标志升级成命令队列 `pcb_test_post_cmd()`（按键回调和远程命令走**同一条**路径，行为一致）；运行序列期间 `SET_VOUT/SET_ILIM/SET_OUTPUT` 返回 `EXIT_BUSY`，急停/停止永远接受；`test_status_t` 增加 `vout_set_mv`、`ilim_set_ma`（用现成的 `pcb_ctrl_vout_setpoint_mv()` 填）、`remote`
- `main.c`：加 `psu_link_init()` 和 `xTaskCreate(psu_link_task, ..., configMINIMAL_STACK_SIZE * 3, NULL, tskIDLE_PRIORITY + 2, NULL)`（优先级 +2：比 UI/测试高，保证命令响应，仍低于 timer 任务）
- `src/app/ui/ui.c`：标题栏加远程/看门狗标识
- `CMakeLists.txt`：**不需要改** — `src/*.c` glob 自动收新文件；`tusb.h` 的包含路径已由 `pico_stdio_usb` 带进编译命令（已在 compile_commands.json 核实）；`pico_stdlib` 已含 `hardware_uart`

## 三、上位机（`scripts/`）

```
scripts/
├─ pyproject.toml          # 仅依赖 pyserial；dev 组 pytest
├─ .python-version  uv.lock  .gitignore  README.md（中文：协议表 + uv 用法 + 无硬件排查）
├─ src/psu_host/
│  ├─ protocol.py          # 与 psu_proto.h 一一对应：CRC/COBS/帧/命令常量
│  ├─ transport.py         # pyserial 打开/关闭/端口枚举（Pico VID 优先）
│  ├─ link.py              # 后台读线程：切帧、不可解码字节按 UTF-8 文本交给日志窗、发送加锁、断线检测
│  ├─ device.py            # 会话：握手、命令+ACK 重试、keepalive、遥测缓存、事件分发、CSV 记录
│  ├─ dummy.py             # 纯 Python 设备模拟器（同一命令表）→ 没有板子也能跑界面和 CLI
│  ├─ cli.py               # monitor / set-v / set-ilim / on / off / safe / test / info / sweep + --csv
│  └─ gui.py               # Tkinter 界面
└─ tests/test_protocol.py  # COBS/CRC 往返、字节向量、单位换算边界、日志文本夹帧的重同步
```

界面：端口选择 + 连接、电压/限流滑块（单位可切 V/‰）+ 急停、输出 ON/OFF、遥测面板、7 项测试结果表、测试运行/停止、Canvas 自绘实时曲线、日志窗、CSV 记录开关。

## 四、验证（我这边跑完再交给你）
1. `uv run pytest` — 协议编解码单测
2. `uv run psu-host --dummy monitor` / `sweep` — CLI 对着模拟器跑通完整命令表（含重试与看门狗）
3. 脚本驱动 Tkinter 界面（dummy 模式 + 定时 `update()`）验证界面构建与刷新路径不抛异常

5. 若本机有 gcc：额外把 `psu_proto.c` 编成本地小程序，与 Python 向量逐字节比对（没有编译器就跳过，并在结论里说明）
